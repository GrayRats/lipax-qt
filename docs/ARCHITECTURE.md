# Архитектура LipaX

LipaX — переводчик игрового текста для KDE Plasma 6 / KWin. Пакет Arch называется
`LipaXQT`, отображаемое имя — `LipaX`. Исполняемый файл `lipa`, desktop ID
`io.lipa.Translator` и каталог настроек `~/.config/lipa` сохранены для совместимости.

## Компоненты

| Компонент | Назначение |
|---|---|
| `crates/core/src/settings.rs` | TOML, проверка значений, миграция старой области, максимум три профиля |
| `capture/kwin.rs`, `capture/geometry.rs`, `capture/geometry.js` | ScreenShot2 и клиентская геометрия окна |
| `capture/portal.rs` | запасной ScreenCast / PipeWire / GStreamer |
| `detect.rs`, `pipeline.rs` | детектор текста, независимое состояние областей, OCR, перевод, повторы |
| `ocr/mod.rs`, `ocr/paddle.rs` | трейт `Ocr`, Tesseract и постоянный Python worker PaddleOCR 3.x |
| `layout.rs` | оценка блока текста, размера, начертания, цветов и размытой подложки |
| `translate/`, `cache.rs` | Google, Yandex, совместимый API, LRU переводов |
| `history.rs`, `diagnostics.rs`, `hotkeys.rs` | история, проверка зависимостей, KGlobalAccel |
| `crates/app/src/bridge.rs` | QObject Controller, очередь событий Rust → GUI, сохранение состояния |
| `qml/TranslationOverlay.qml` | перемещаемое окно перевода, четыре вида фона |
| `qml/InplaceText.qml` | перевод над исходным блоком текста |
| `qml/RegionFrame.qml` | независимая рамка каждой области |
| `qml/SettingsWindow.qml`, `qml/HistoryWindow.qml` | настройки и отдельное окно истории |
| `crates/app/src/app_icon.h` | иконка, KWindowEffects blur, область ввода Wayland, буфер обмена |

GUI работает в потоке Qt, захват, процессы OCR и сеть — в Tokio. Ядро не зависит от Qt.
QML использует `org.kde.layershell`; blur обычного overlay использует KF6WindowSystem.

## Области и pipeline

Можно хранить не более **трёх областей**. Четвёртая блокируется в форме и при
нормализации конфигурации. Новая область создаётся выключенной. По умолчанию включена
только активная область; опция одновременного распознавания разрешает включить до трёх.
У каждой свои координаты, языки, OCR, интервал, debounce и режим рамки. Координаты
хранятся в долях клиентского кадра, поэтому не зависят от положения окна на мониторе.

```text
Кадр области → детектор изменения текста → debounce → OCR → сравнение текста
                                                       → кэш → перевод → GUI / история
                                                       → оценка блока для наложения
```

Детектор сравнивает контрастные края букв, а не только среднюю яркость сцены.
Debounce ждёт стабилизации; непрерывно меняющаяся сцена допускает OCR не реже раза
в две секунды. Области обрабатываются последовательно, очередь старых кадров не копится.
Состояние детектора, ошибки и интервал принадлежат каждой области отдельно.

После ошибки повтор выполняется даже на неизменном кадре: задержки 2, 4, 8, 16,
30 секунд. Общий бюджет операции/серии ошибок ограничен 60 секундами; затем
автоповтор прекращается, остаётся красно-жёлтое сообщение с причиной и кнопка
«Повторить». Ручной повтор сбрасывает остановку. Успешный результат убирает ошибку.

`Event::Translation` обновляет перевод и историю. `Event::Placement` обновляет
только положение/подложку уже известного текста или скрывает исчезнувший текст;
повторные записи истории при этом не создаются.

## Захват без декораций

KWin `CaptureWindow` вызывается с `include-decoration=false`, `include-shadow=false`,
`include-cursor=false`, `native-resolution=true`. Захватывается конкретное окно:
рамки и перевод находятся на других поверхностях и не становятся входом OCR.
Доступ задаёт `.desktop` с `X-KDE-DBUS-Restricted-Interfaces=org.kde.KWin.ScreenShot2`;
`Exec` должен совпадать с абсолютным путём запущенного бинарника.

Скрипт KWin передаёт `clientGeometry`, `frameGeometry`, `bufferGeometry` и обновляет
их при перемещении/изменении размеров. `client_crop` сопоставляет размер кадра
с этими прямоугольниками, учитывает масштаб и обрезает внешние декорации/тени.
Рамки областей и наложение используют тот же клиентский прямоугольник. При отсутствии
геометрии ложная рамка не рисуется; неудачная загрузка скрипта повторяется через 30 с.

**Граница возможностей:** GTK/CSD может рисовать заголовок внутри собственного
клиентского содержимого. KWin не сообщает границу такого заголовка; область OCR
следует выделять ниже него. Внешняя CSD-тень при этом исключается.

Portal запрашивает отдельное окно через стандартный диалог. PipeWire fd передаётся
`gst-launch-1.0`; поток PNG разделяется на кадры. При остановке процесса показываются
код завершения и хвост stderr; старый кадр не выдаётся как актуальный. Portal не даёт
UUID и достоверной геометрии окна: координаты области относятся к полученному кадру,
автоматическая обрезка декораций и наложение над оригиналом недоступны. Используется
обычный overlay с выбором монитора в настройках.

## Рамки и обычный overlay

Рамка области отделена от рамки окна перевода. У каждой области свой таймер появления.
Режимы: пурпурно-чёрный узор, сплошная обводка выбранного цвета, выключено, только
после выделения с плавным исчезновением. При закреплении перевода постоянные рамки
можно приглушать или скрывать. Рамки не принимают ввод и не попадают в OCR.

Обычный перевод имеет четыре вида: фон с размытием KWin, прозрачный фон с тенью
текста, приглушённый тёмный/светлый фон, сплошной настраиваемый фон. Рамка по умолчанию
пурпурная, полупрозрачная; цвет, узор, прозрачность и толщина настраиваются.

Незакреплённое окно имеет более толстую рамку, скругление, кнопку закрытия и
перетаскивается ЛКМ. MMB переключает закрепление. Закреплённое окно пропускает
нажатия через центральную часть; ручка закрепления остаётся видимой и доступной,
даже если рамка исчезла. Wayland input region задаётся через `QWindow::setMask`.
На X11 этот частичный пропуск не включается, чтобы не обрезать изображение окна.

Layer-shell `LayerOverlay` держит перевод поверх обычных окон, клавиатурный фокус
не запрашивается. Положение задаётся отступами от выбранного экрана. Автовыбор
использует наибольшее пересечение с окном игры; есть ручной выбор монитора. Положение,
размер и закрепление сохраняются. Работу поверх конкретной полноэкранной игры
следует дополнительно проверять в её режиме вывода.

## Наложение текста поверх оригинала

`translation_display = "inplace"` создаёт отдельную layer-shell поверхность для
каждой обрабатываемой области, только над найденным блоком текста. Обычный overlay
в это время скрыт. Геометрия считается так: клиентское окно → нормализованная область
→ нормализованный блок текста → координаты экрана. Учитывается масштаб захвата.

`layout.rs` разделяет яркости методом Оцу, оценивает строки и границы по проекциям.
Цвета берутся из пикселей текста и фона вокруг него. Высота строк и толщина штрихов
дают оценку размера и жирности. Семейство приблизительно классифицируется как
sans-serif / serif / monospace; точное имя исходного шрифта из кадра не определяется.
Шрифт можно переопределить в настройках.

Пиксели исходных букв заменяются оценённым цветом фона; фрагмент уменьшается,
затем растягивается со сглаживанием. Эта размытая подложка и цветная заливка скрывают
оригинал в пределах блока. `Text.Fit` уменьшает перевод под исходные размеры.
Это эвристический режим: на сложном игровом фоне определение блока и стиля может
ошибаться; для таких сцен стоит выбирать более тесную область либо обычный overlay.

MMB по наложению **скрывает перевод**. Вернуть его можно переключателем «Поверх игры»
или горячей клавишей. Перемещение и закрепление относятся к обычному overlay:
наложение следует за оригинальным блоком. Пока наложение видимо, его поверхность
принимает мышь для обработки MMB; клавиатурный фокус не забирается.

## Настройки, история и диагностика

Внешний вид меняется сразу, конфигурация записывается после 500 мс без изменений
и при закрытии формы. Файл `~/.config/lipa/config.toml` записывается атомарно с правами
0600. Старые настройки мигрируют; сброс раздела затрагивает только его поля.

Вкладки: «Распознавание», «Перевод и захват», «Окно перевода», «Внешний вид перевода»,
«Область», «Клавиши», «Статус», «О программе». Репозитории в интерфейсе перечислены
только в «О программе»: автор GrayRat, анимированная SVG-иконка, бегущая строка,
основной репозиторий и источники зависимостей.

«Перевод → История…» открывает отдельное окно: время, область, оригинал, перевод,
копирование, очистка, лимит, отключение записи и сохранения между запусками.
История в памяти ограничена настройкой; файл записывается атомарно с правами 0600.
«Статус» проверяет Tesseract, PaddleOCR/Python, модели, PipeWire и GStreamer и
показывает команды установки. Подключение PaddleOCR описано в [PaddleOCR.md](PaddleOCR.md).

## Сборка и проверки

`./packaging/build-local.sh` собирает снимок рабочего дерева, выполняет Rust- и
QML-тесты и создаёт `dist/LipaXQT-0.3.0-3-x86_64.pkg.tar.zst`. Пакет содержит бинарник,
desktop-файл с именем LipaX, SVG, лицензию и документацию.

Проверки выполнены на Qt 6.11.2 и текущей KDE/Wayland-сессии. Отдельной проверки
на Qt 6.12 не было. Набор QML-тестов проверяет три области/отказ четвёртой, рамки,
все виды обычного overlay, MMB, перемещение, наложение, вкладки и историю.
`examples/geometry.rs` позволяет сохранить клиентский кадр по UUID KWin.
Результаты и оставшиеся сценарии перечислены в [IMPROVEMENTS.md](IMPROVEMENTS.md).
