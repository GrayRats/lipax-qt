# RapidOCR (необязательный движок)

RapidOCR — это модели **PP-OCRv5** (детектор текста DBNet, классификатор ориентации строки и
распознаватель с CTC) в формате ONNX. LipaX выполняет их **в своём процессе** через ONNX Runtime
(крейт [`ort`](https://ort.pyke.io/)): без Python, без отдельного worker-процесса, без обмена
через stdin/stdout. Кадр не покидает память приложения.

Tesseract остаётся движком по умолчанию. RapidOCR выбирается в «Настройки → Распознавание →
Движок распознавания → **RapidOCR (PP-OCRv5)**», для отдельной области — в её настройках. В режиме
**Авто** он работает «вторым мнением» после Tesseract (см. ниже).

## Установка

Нужна системная библиотека ONNX Runtime. В Arch Linux / CachyOS:

```bash
sudo pacman -S onnxruntime-cpu
```

Пакет даёт `onnxruntime` и `/usr/lib/libonnxruntime.so*`; в PKGBUILD LipaX он указан в `optdepends`.
Библиотека загружается при первом распознавании через RapidOCR (`ort`, режим `load-dynamic`).
Бинарник `lipax` с ней не слинкован, поэтому без неё запускается и работает с Tesseract/PaddleOCR.
Нужна ONNX Runtime **1.17 или новее**: более старую `ort` откажется загружать с понятной ошибкой.

Где ищется библиотека, по порядку:

1. переменная окружения `LIPAX_ORT_LIBRARY` (путь к `libonnxruntime.so`);
2. `ORT_DYLIB_PATH` (стандартная переменная `ort`);
3. `/usr/lib/libonnxruntime.so.1`, `/usr/lib/libonnxruntime.so`, `/usr/lib64/…`, `/usr/local/lib/…`.

Путь сразу приводится к абсолютному (`canonicalize`) и дальше от текущего каталога не зависит.
Библиотека загружается один раз за жизнь процесса. Если её не было и вы установили её при
запущенном LipaX, перезапуск не нужен: следующая попытка распознавания найдёт её сама.

## Модели

Модели **не входят в пакет** и **никогда не скачиваются сами**. В пакете есть только каталог
`crates/core/src/ocr/ocr_models_catalog.json`, встроенный в бинарник: id, письменность, языки,
вариант (mobile/server), лицензия, а также URL, размер и SHA-256 каждого файла.

Источник — репозиторий [RapidAI/RapidOCR на ModelScope](https://www.modelscope.cn/models/RapidAI/RapidOCR),
закреплённый на теге **v3.10.0**: ссылки вида `…/resolve/v3.10.0/onnx/PP-OCRv5/…`, поэтому
обновление ветки `master` не ломает проверку хешей. Лицензия моделей — Apache-2.0.

Каждый набор состоит из четырёх файлов: `det` (детектор), `cls` (ориентация строки), `rec`
(распознаватель) и `dict` (словарь распознавателя). Наборы лежат в
`~/.local/share/LipaX/ocr-models/<id>/` (`dirs::data_local_dir()`).

| id | Что читает | Размер |
|---|---|---:|
| `en-mobile` | английский | 14 МБ |
| `latin-mobile` | латиница: немецкий, французский, испанский, итальянский, португальский, польский и др. | 14 МБ |
| `eslav-mobile` | кириллица: русский, украинский, белорусский | 14 МБ |
| `cyrillic-mobile` | кириллица: болгарский, сербский, македонский, казахский, монгольский | 14 МБ |
| `ch-mobile` | китайский (упрощённый и традиционный) и японский | 23 МБ |
| `ch-server` | то же, модели server | 180 МБ |
| `korean-mobile` | корейский | 19 МБ |
| `el-mobile`, `th-mobile`, `arabic-mobile`, `devanagari-mobile`, `ta-mobile`, `te-mobile` | греческий, тайский, арабское письмо, деванагари, тамильский, телугу | по 14 МБ |

**Скачивание** — кнопка «Скачать» в блоке «Модель RapidOCR» (вкладка «Распознавание»).
Файлы пишутся как `*.part` во временный каталог `.download-*` внутри `ocr-models`.
У каждого проверяются размер и SHA-256 по каталогу, и только потом набор целиком переносится
в `<id>/`. Прежняя установка сохраняется до успешной замены. Ошибка сети, обрыв или неверный
хеш оставляют прежнее состояние и показывают сообщение с причиной («Проверьте подключение к сети
и повторите загрузку»). Загрузка идёт в отдельном потоке Qt; при выходе из приложения она
отменяется, а недокачанные файлы удаляются.

**Удаление** — кнопка «Удалить» (с подтверждением). Остальные скачанные наборы перечислены
ниже, у каждого своя кнопка удаления.

**Вручную, без приложения** (например, на машине без сети) скачайте четыре файла набора по URL из
каталога в `~/.local/share/LipaX/ocr-models/<id>/` под именами из поля `name`. LipaX сверит размер
и SHA-256 перед первым использованием; повреждённый набор не загружается («удалите модель и
скачайте её заново»).

Каталог обновляется программой на Rust: `cargo run -p lipa-core --example update_catalogs -- ocr`. Она читает только
метаданные файлов (размер и SHA-256) через API ModelScope и Hugging Face, сами модели не скачивает. Флаг
`--listing файл.json` берёт сохранённый ответ API ModelScope вместо сети. Установить или удалить модель из
каталога без интерфейса можно так: `cargo run -p lipa-core --example ocr_model -- download|remove|list [id]`.

## Языки

Модель выбирается по **основному** языку из «Язык распознавания» (код Tesseract), как у PaddleOCR:

| Коды Tesseract | Модель |
|---|---|
| `eng` | `en` |
| `deu fra spa ita por pol nld swe dan nor ces slk slv hrv hun tur ind msa est lit isl bos sqi afr lat cym gle` | `latin` |
| `rus ukr bel` | `eslav` |
| `bul srp mkd kaz mon` | `cyrillic` |
| `chi_sim chi_tra jpn` | `ch` (mobile или server) |
| `kor` | `korean` |
| `ell`, `tha`, `ara fas urd`, `hin mar nep san`, `tam`, `tel` | `el`, `th`, `arabic`, `devanagari`, `ta`, `te` |

Для строки вида `rus+eng` RapidOCR читает только `rus`. Настройки предупреждают об этом:
«RapidOCR читает только основной язык («rus»); eng распознаёт только Tesseract». Модель
`ch` читает и латиницу, так что японский текст с английскими словами распознаётся целиком.
Язык без модели — ошибка настройки с предложением выбрать другой основной язык или Tesseract.

## Как идёт распознавание

1. Кадр уменьшается для детектора: длинная сторона не больше 1600 px, короткая не меньше
   64 px, обе стороны кратны 32. Кадр 1920×1080 читается в 1600×896, полоса субтитров
   1280×200 — в 1280×192. Порядок каналов BGR, нормализация ImageNet, как при обучении PP-OCR.
2. Карта вероятностей DBNet превращается в повёрнутые прямоугольники (порог 0.3, порог бокса 0.5,
   `unclip` 1.6, минимальная сторона 3 px), как в `DBPostProcess` PaddleOCR. Боксы упорядочены
   сверху вниз и в одной строке слева направо.
3. Каждый бокс вырезается выпрямленным (вертикальный бокс поворачивается). Если классификатор
   PP-LCNet склоняется к тому, что строка перевёрнута (больше 0.5), она распознаётся и в исходном,
   и в повёрнутом на 180° виде; повёрнутое чтение берётся, только если оно увереннее хотя бы на 0.1
   (почти симметричная строка вроде «NOW»/«MON» читается обоими способами). Сам по себе классификатор строку
   не переворачивает (почему — в разделе «Результаты»). Если перевёрнутыми оказались все строки,
   кадр целиком вверх ногами, и порядок строк разворачивается.
4. Распознаватель получает строки пачками по 6, высотой 48 px, сгруппированными по пропорциям.
   Его вероятности декодируются жадным CTC по словарю модели: пустой класс — 0, пробел — последний.
5. Каждый бокс становится строкой `OcrLine`: прямоугольник в пикселях входного кадра и уверенность
   0–100 (среднее по символам строки). Уверенность результата — среднее по всем символам.

Сессии ONNX Runtime создаются один раз на модель (не больше трёх одновременно, по числу областей)
и переиспользуются. Вывод идёт в `spawn_blocking`, вне потока конвейера.

## Настройки

| Ключ `config.toml` | По умолчанию | Что делает |
|---|---|---|
| `recognition.engine = "rapidocr"` | `tesseract` | движок; для области — `capture.regions[].engine` |
| `recognition.rapid_threads` | `0` | потоки ONNX Runtime; `0` — половина ядер, но не больше 4 (на 12-поточном Ryzen 5 5600 — 4) |
| `recognition.rapid_use_gpu` | `false` | использовать GPU, если он есть в установленной ONNX Runtime |
| `recognition.rapid_variant` | `mobile` | `mobile` или `server` (server есть только для `ch`) |

Потоки ONNX Runtime не крутятся вхолостую между кадрами (`allow_spinning = 0`): процессорное
время между кадрами остаётся игре. Классификатору ориентации хватает двух потоков.

**Фильтры изображения.** Ручные фильтры (инверсия, контраст, резкость, бинаризация) применяются
до движка, как у Tesseract и PaddleOCR. Автоматическая бинаризация шумных кадров («Подбирать
фильтры по кадру автоматически») для RapidOCR **не включается**: PP-OCR лучше читает цветной или
серый кадр, чем двухцветный.

**Порог уверенности.** С RapidOCR действует не меньше **50 %** (если порог не 0). Это значение
`drop_score` из PaddleOCR 2.x и порог `text_score` самого RapidOCR: PP-OCR оценивает чистую
строку в 0.9 и выше, а текстурный фон читает «словами» с уверенностью 0.4–0.6. Замеры на
настоящих моделях (раздел «Результаты») подтверждают, что настоящий текст получает 96–100 %;
мусора на тестовых кадрах не появилось, поэтому верхнюю границу для него подобрать не удалось.

## Режим «Авто»

Сначала читает Tesseract. Если его уверенность ниже 60 %, кадр перечитывает **RapidOCR** (только
с ручными фильтрами), и берётся более уверенный результат. Если RapidOCR недоступен (нет модели,
нет ONNX Runtime, ошибка выполнения), на этом кадре вместо него работает PaddleOCR, как раньше.
После ошибки RapidOCR не пробуется **5 минут** (`rapid_down_until`, по образцу `paddle_down_until`),
чтобы не проверять отсутствующую модель на каждом кадре. Значит, после скачивания модели в режиме
«Авто» RapidOCR включится в течение пяти минут или после перезапуска слежения.

Если RapidOCR выбран **явно**, а модели или библиотеки нет, другой движок его не подменяет:
распознавание завершается ошибкой с действием («Скачайте её: Настройки → Распознавание →
RapidOCR → Скачать», «Установите её: sudo pacman -S onnxruntime-cpu»).

## GPU

Флажок «Использовать GPU, если доступен» пробует провайдеры ONNX Runtime CUDA, MIGraphX и ROCm,
но только те, с которыми собрана установленная библиотека. `onnxruntime-cpu` собран без них,
поэтому RapidOCR работает на CPU и пишет в журнал: «GPU для RapidOCR недоступен: ONNX Runtime
собран без CUDA/MIGraphX/ROCm, используется CPU». Если провайдер есть, но не регистрируется
(нет драйвера или устройства), это тоже записывается в журнал, и сессия создаётся на CPU.
Ошибки пользователю в этих случаях нет. Чтобы GPU заработал, нужна GPU-сборка ONNX Runtime из
репозитория вашего дистрибутива, путь к ней можно задать в `LIPAX_ORT_LIBRARY`.

## Диагностика

- **«Распознавание» → блок «Модель RapidOCR»** показывает выбранную модель и её состояние
  («не скачана», «загрузка N %», «готова»), игнорируемые языки и путь к ONNX Runtime. Если
  библиотеки нет, там же команда установки с кнопкой «Копировать». Проверка запускается сама при
  выборе движка, смене языка, варианта моделей или числа потоков; кнопка «Проверить снова» — по требованию.
  Проверка читает только диск: выбранная модель сверяется по SHA-256, остальные — по размеру.
- **«Статус»** при движке RapidOCR или «Авто» показывает строки «RapidOCR: ONNX Runtime» и
  «Модель RapidOCR».
- **Журнал** (`component=rapidocr`): загрузка ONNX Runtime (путь), загрузка моделей (id, потоки,
  GPU, время), по каждому кадру на уровне `debug` — время детектора, классификатора и распознавателя.

| Сообщение | Что сделать |
|---|---|
| «не найдена библиотека ONNX Runtime» | `sudo pacman -S onnxruntime-cpu`, затем «Проверить снова» |
| «не удалось загрузить ONNX Runtime … expected version >= '1.17.x'» | обновить `onnxruntime` |
| «модель … не скачана» | «Скачать» в настройках |
| «файлы модели … повреждены (SHA-256 не совпадает)» | «Удалить», затем «Скачать» |
| «Не удалось скачать модель … Проверьте подключение к сети» | проверить сеть и повторить |
| «язык … не поддерживается моделями PP-OCRv5» | выбрать другой основной язык или Tesseract |
| «словарь … не подходит к распознавателю» | удалить и скачать набор заново |

## Тесты и замеры

Юнит-тесты (`cargo test -p lipa-core`) проверяют разбор словаря, CTC-декодирование, сопоставление
языков, каталог, проверку хешей, загрузку с `.part` и ошибку без сети. Отдельный тест прогоняет
весь конвейер через **настоящую** системную ONNX Runtime на крошечных синтетических ONNX-моделях,
собранных прямо в тесте (без скачивания); без библиотеки он пропускается.

Проверка на настоящих моделях — `crates/core/tests/rapid_native.rs` (`#[ignore]`, запускается явно):

```bash
LIPAX_RAPID_TEST_MODELS=~/.local/share/LipaX/ocr-models \
cargo test --release -p lipa-core --test rapid_native -- --ignored --nocapture --test-threads=1
```

Нужны наборы `en-mobile`, `eslav-mobile` и `ch-mobile`. Другие переменные:
`LIPAX_RAPID_TEST_ORT` — путь к библиотеке, `LIPAX_RAPID_TEST_THREADS` — число потоков,
`LIPAX_RAPID_TEST_PADDLE_PYTHON` — Python с PaddleOCR 3.x для сравнения,
`LIPAX_RAPID_TEST_SKIP_TESSERACT=1` — без Tesseract (полный прогон длится около 6 минут, почти всё
время — японский Tesseract на 1920×1080, около 48 с на кадр; без него — секунды).
Строки на английском и русском взяты из готовых фикстур (`tests/fixtures/fonts/Inter-*-dark.png`),
японская рисуется Rust-кодом из `tests/common` (шрифт Noto Sans CJK из пакета, Python не нужен).
`reads_english_russian_and_japanese` читает каждую строку отдельно, в кадрах 1280×200 и 1920×1080 и
перевёрнутой на 180° и проверяет CER ≤ 0.1 (en, ru) и ≤ 0.2 (ja), уверенность ≥ 50 и координаты строк. `benchmark_frames_against_tesseract_and_paddle` вставляет строку в игровой кадр
1280×200 (полоса субтитров) и 1920×1080 (тёмный градиент с зерном) и печатает таблицу: медиану
задержки по 5 прогонам после прогрева, CER и WER. Результат каждого движка предварительно чистится
так же, как в LipaX (`filter::clean` с порогом этого движка).

### Результаты

Ryzen 5 5600 (6 ядер / 12 потоков), CachyOS, ONNX Runtime 1.29.0 (`onnxruntime-cpu`), Tesseract 5.5.3,
сборка `--release`, 4 потока RapidOCR.

PaddleOCR в сравнение не входит: он работает через Python, которого в этой системе нет
(`LIPAX_RAPID_TEST_PADDLE_PYTHON` добавляет его в таблицу тому, у кого он установлен). Строки RapidOCR
перемерены на свободной машине (`LIPAX_RAPID_TEST_SKIP_TESSERACT=1`), строки Tesseract взяты из полного
прогона того же теста. Японская строка рисуется шрифтом Noto Sans CJK средствами Rust (раньше — через
Python/PIL, поэтому цифры Tesseract для японского отличаются от прежних). Русская фикстура обрезана
после «ли», поэтому идеальное чтение даёт CER 0.054.

| Кадр | Язык | Движок | Задержка, мс (медиана) | CER | WER |
|---|---|---|---:|---:|---:|
| 1280×200 | eng | RapidOCR (PP-OCRv5 mobile) | 56 | 0.000 | 0.000 |
| 1280×200 | eng | Tesseract 5.5.3 | 227 | 0.000 | 0.000 |
| 1920×1080 | eng | RapidOCR (PP-OCRv5 mobile) | 302 | 0.000 | 0.000 |
| 1920×1080 | eng | Tesseract 5.5.3 | 5619 | 3.735 | 2.750 |
| 1280×200 | rus | RapidOCR (PP-OCRv5 mobile) | 92 | 0.054 | 0.143 |
| 1280×200 | rus | Tesseract 5.5.3 | 431 | 0.054 | 0.143 |
| 1920×1080 | rus | RapidOCR (PP-OCRv5 mobile) | 317 | 0.054 | 0.143 |
| 1920×1080 | rus | Tesseract 5.5.3 | 8066 | 6.486 | 5.714 |
| 1280×200 | jpn | RapidOCR (PP-OCRv5 mobile) | 53 | 0.048 | — |
| 1280×200 | jpn | Tesseract 5.5.3 | 2637 | 3.000 | — |
| 1920×1080 | jpn | RapidOCR (PP-OCRv5 mobile) | 283 | 0.048 | — |
| 1920×1080 | jpn | Tesseract 5.5.3 | 57360 | 53.952 | — |

CER и WER больше 1 значат, что лишнего текста больше, чем верного: на кадре 1920×1080 Tesseract
читает зерно фона как «слова», и часть из них проходит порог уверенности. Задержка Tesseract
включает его двукратное увеличение кадра (как в LipaX) и запуск процесса. RapidOCR на тех же кадрах
лишнего не находит и работает в 4–200 раз быстрее. Первый кадр после выбора движка дольше:
модели загружаются (около 0,3 с для набора mobile).

Русская строка 1280×200 стоит 92 мс вместо 56: классификатор склоняется к «вверх ногами» (0.77), и
строку распознают дважды (см. «Как идёт распознавание», п. 3).

**Что выявили настоящие модели.**

- CDN ModelScope отвечает 403 на запрос без `User-Agent`. LipaX отправляет `LipaX/<версия>`;
  тестовый сервер в юнит-тестах так же отказывает без заголовка.
- Классификатор ориентации на длинной узкой строке поверх текстурного фона назвал правильную русскую
  строку перевёрнутой (0.92), и при порядке PaddleOCR («повернуть, если больше 0.9») строка терялась
  целиком (CER 1.000 на 1920×1080). На 193 строках фикстур, вырезанных плотно, он не ошибся ни разу.
  Теперь его ответ — подсказка, решает распознаватель.
