# Архитектурный аудит 1.4.4

Дата: 2026-11-19. Ветка `work-1.4.4`. Метод: три независимых ревьюера (Opus 5.5, только чтение: захват и KWin, конвейер и
мост, данные OCR/перевода/настроек) плюс собственный разбор. Каждое исправление проверено по коду до правки; пункты,
которые ревьюеры пометили «НЕ ПОДТВЕРЖДЕНО», не правились. Живой проверки в Proton-игре не было.

## Проверка после правок

- `cargo clippy --release --workspace --all-targets`: без предупреждений.
- `ocr_accuracy` по 16 кадрам: 0 расхождений с замером до аудита (r10 → r11), распознавание RapidOCR не затронуто.
- Регрессионный тест `an_auto_tune_asked_right_after_a_settings_change_is_not_lost` проверен на обоих состояниях кода:
  без исправления падает, с исправлением проходит.

## Не исправлено: риски и решения

Отсортировано по важности. Все пункты подтверждены чтением кода, но не воспроизводились на живой системе.

1. **Диалог portal открывается из автоматического захвата** (`capture/portal.rs:379-386`). Без токена или после отмены
   диалога конвейер сам открывает диалог выбора окна на 2, 4, 8, 16 и 30 с, пока не кончится бюджет ошибок; диалог может
   закрыться посреди выбора по 60-секундному тайм-ауту. Исправление: не вызывать `spawn_session` из `latest_png` при пустом
   токене, хранить ошибку восстановления и не повторять до явного `select_window`; заменять сессию только после успеха.
   Затронут только режим portal (не KWin); изменение меняет поведение выбора окна, поэтому нужна живая проверка.
2. **Перезапуск KWin** (`capture/kwin.rs:19`, `OnceCell<ClientGeometry>`): таблицы окон, свёрнутости и фокуса скрипта
   остаются прежними навсегда. Исправление: следить за `NameOwnerChanged` для `org.kde.KWin`, очищать состояние и
   перезагружать скрипт (`Mutex<Option<Arc<ClientGeometry>>>`). Требует проверки на живом KWin.
3. **Отмена устаревшего чтения не останавливает RapidOCR/MeikiOCR**: `spawn_blocking` под общим `StdMutex` движка
   продолжает работу, новое чтение ждёт в очереди (`pipeline/mod.rs:519`, `rapid.rs:698`, `meiki.rs:418`). Исправление:
   флаг отмены между стадиями det и rec или `probe = None` для движков внутри процесса. Нужен замер задержки на
   анимированном фоне.
4. **Синхронный дисковый ввод-вывод в GUI-потоке**: `publish_history` переписывает весь файл истории при каждом патче
   настроек, PNG-подложки кодируются в GUI-потоке (`bridge/invokables.rs`). Исправление: писать историю только при
   изменении `history_*` и вне GUI-потока.
5. **SHA-256 всей модели Bergamot на каждый перевод** (`translate/bergamot.rs` → `models.rs:274`): десятки мс CPU на
   вызов в `spawn_blocking`. Исправление: кэш по `(путь, размер, mtime)`; сначала замерить.
6. **Отмена установки модели не работает на синхронных шагах** (хеширование, обход каталогов, `fs::copy`,
   `translate/models.rs:334-359`). Исправление: `spawn_blocking` и проверка отмены между файлами.
7. **Диагностика Bergamot теряется при раннем выходе процесса** (`try_join!` бросает EPIPE раньше stderr,
   `bergamot.rs:136`). Исправление: `join!`, сначала статус и stderr.
8. **`unless_stale` не опрашивает работу во время пробного захвата** (`pipeline/mod.rs:532`): задержка до времени захвата
   каждые 150 мс. Исправление: `grab` внутри `select!` вместе с работой.

Дополнительно:
- Тест на «`auto` без Tesseract» не написан: движки не подменяются в `AnyOcr`; изменение проверено сборкой, тестами OCR
  и неизменностью отчёта по кадрам. Для теста нужен трейт движка в `AnyOcr`.
- Overlay (DPI, Z-order, позиционирование): ревью QML не выявило дефектов; QML-тесты и тесты размещения зелёные. Живая
  проверка на нескольких мониторах и дробных масштабах не выполнялась.
- Ревьюеры не нашли проблем в: `kwin.rs` (взаимная блокировка на pipe, `decode`, HiDPI-обрезка), порядке блокировок
  `geometry.rs`, `process.rs`, `instance.rs`, `text.rs` (срезов по байтам нет), `paddle.rs`, `settings/migrate.rs`,
  откате `install` моделей.
