# Доработки 0.3.0-2

- Ошибка остановки gst-launch с кодом завершения и последними 8 КиБ stderr;
  старый кадр после сбоя не возвращается, диалог portal не открывается в цикле.
- Portal запрашивает только окно: служебная рамка и перевод находятся на отдельных
  поверхностях и не попадают в OCR. KWin по-прежнему исключает декорации и курсор.
- Рамка использует `clientGeometry` через небольшой скрипт KWin 6. Высота заголовка
  не угадывается. Если геометрия недоступна, нет рамки с неверными координатами.
- Overlay автоматически выбирает монитор с наибольшей площадью пересечения с игрой.
  Положение обновляется при переносе окна. Размер и отступы ограничены экраном.
  Для portal есть ручной выбор экрана: портал не сообщает UUID/положение окна игры.
- PaddleOCR 3.x за трейтом Ocr, постоянный Python worker, переключение в настройках.
- Настройки разделены на четыре вкладки, подписи переносятся, кнопки закреплены снизу.
  Основное окно увеличено; длинные ошибки доступны целиком.
- Собственная SVG-иконка в ресурсах Qt и пакете hicolor; задан desktop file ID.

## Предложения для следующего этапа

1. Профили по игре: свои область, язык, OCR и положение перевода.
2. Отдельный просмотр исходного кадра и OCR-результата для настройки качества.
3. Повтор OCR/перевода после временной ошибки с ограниченной частотой, даже если
   изображение с текстом больше не меняется.
4. Режим проверки зависимостей PaddleOCR прямо из настроек и локальный выбор модели.
5. Интеграционные проверки на двух мониторах с разным масштабом и живым portal.

## Проверки

- Модульные тесты ядра: PNG, авария процесса, OCR-протокол, геометрия, pipeline.
- QML-тест: четыре вкладки при минимальном размере окна, сохранение выбора OCR.
- Живой KWin: у тестового Qt-окна внешняя геометрия 640×428 при y=324,
  клиентская 640×400 при y=352; разница заголовка 28 px учтена точно.
- PaddleOCR с настоящими моделями и перенос между физическими мониторами
  требуют отдельной проверки; в текущей системе PaddleOCR отсутствует.
